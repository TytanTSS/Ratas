# Ратас — движок фэнтези-RPG для терминала

Ратас — это RPG в реальном времени, которая работает прямо в терминале. Графика собрана из ASCII-символов, камера смотрит сверху. Есть и графический режим в отдельном окне: пиксель-арт, динамический свет, частицы. Мир генерируется случайно. Можно играть вместе по сети, а NPC и элитные враги могут думать с помощью Claude.

## Готовые сборки

Собирать ничего не обязательно: на странице [Releases](https://github.com/TytanTSS/Ratas/releases) лежат архивы для Windows (x64 и ARM), macOS (одна сборка для Apple Silicon и Intel) и Linux, а также выделенный сервер для Linux. Распакуйте архив и запустите `ratas` (`ratas.exe` на Windows). Особенности первого запуска на macOS и Windows описаны в заметках к релизу.

## Быстрый старт

Нужен Go 1.26 или новее. Если Go не установлен, удобнее собрать через [mise](#сборка-через-mise).

```bash
go build -o ratas ./cmd/ratas
```

```bash
./ratas
```

Полезные флаги:

```bash
./ratas -new -seed 42 -name Арагорн -class warrior   # сразу в новый мир
./ratas -new -host                                   # новый мир, открытый для друзей
./ratas -join 192.168.1.20:7777 -name Леголас        # подключиться к другу
./ratas -load <слот>                                 # загрузить сохранение
./ratas -server -seed 7 -port 7777                   # выделенный сервер без интерфейса
./ratas -gfx                                         # графический режим в отдельном окне
./ratas -gfx -join 192.168.1.20:7777                 # любой флаг работает и с окном
```

Лучше всего играть в терминале размером от 100×30. Минимальный размер — 80×24.

## Сборка через mise

[mise](https://mise.jdx.dev) сам ставит нужную версию Go и хранит команды сборки в `mise.toml`. Устанавливать Go вручную не нужно.

Один раз после клонирования:

```bash
mise trust
```

```bash
mise install
```

Первая команда разрешает mise читать `mise.toml` из этой папки, вторая ставит Go 1.26 (только для проекта, системный Go не трогается).

Дальше все действия — задачи mise:

| Команда | Что делает |
|---|---|
| `mise run build` | собирает `./ratas` (терминал и графическое окно) |
| `mise run play` | собирает и запускает игру в терминале |
| `mise run gfx` | собирает и запускает графический режим |
| `mise run build-server` | собирает `./ratas-server` без графики: не нужны cgo и X11/OpenGL |
| `mise run server` | собирает и запускает выделенный сервер |
| `mise run test` | все тесты |
| `mise run lint` | `go vet` с графикой и без неё |
| `mise run check` | форматирование, vet и тесты — перед коммитом |
| `mise run dist` | релизные сборки в `dist/` |
| `mise run sheets` | PNG-листы со всеми моделями существ и тайлами |
| `mise run shots` | сценарий со скриншотами графического режима (нужен экран) |
| `mise run clean` | удаляет собранные файлы |

Флаги игры передаются после `--`:

```bash
mise run play -- -new -seed 42 -class mage
```

```bash
mise run server -- -seed 7 -port 7777
```

`mise tasks` показывает все задачи с описаниями. Папки для `sheets` и `shots` задаются переменными `SHEETS_DIR` и `SHOTS_DIR` (по умолчанию `/tmp/ratas-sheets` и `/tmp/ratas-shots`).

`mise run dist` собирает с любой машины:

| Файл | Платформа |
|---|---|
| `ratas-macos-arm64` | macOS на Apple Silicon |
| `ratas-macos-amd64` | macOS на Intel |
| `ratas-windows-amd64.exe` | Windows |
| `ratas-server-linux-amd64` | сервер для Linux без графики |

Полную версию для Linux с графическим окном кросс-компиляцией не собрать: Ebitengine на Linux нужен cgo. Её собирают на самом Linux через `mise run build`, предварительно поставив dev-пакеты X11/OpenGL (см. раздел «Графический режим»).

## Управление

| Клавиша | Действие |
|---|---|
| WASD / стрелки | ходить (удерживайте для бега); шаг в сторону врага — атака |
| Пробел | атаковать соседнего врага |
| E / Enter | говорить, открыть дверь или сундук, пройти по лестнице |
| 1–6 | умения с панели (в терминале цель выбирается автоматически, в окне — под курсором мыши) |
| Q / R | зелье здоровья / маны |
| I / K / C / J | инвентарь / навыки / персонаж / журнал заданий |
| M или Tab | карта уровня |
| T | чат |
| F5 | сохранить (только хозяин мира) |
| Esc | меню; в одиночной игре включает паузу |
| F9 | окно администратора (только в режиме `-admin`) |
| Ctrl+V | вставить текст из буфера обмена в поле ввода (также Cmd+V и Shift+Insert) |

Горячие клавиши работают и в русской раскладке: `ц` = W, `ш` = I и так далее.

На Linux для Ctrl+V нужен `xclip`, `xsel` или `wl-clipboard`; вставка через меню терминала (Ctrl+Shift+V) работает и без них, при этом многострочный текст не отправляет поле раньше времени.

## Режим администратора

Для тестирования игру можно запустить с флагом `-admin`:

```bash
./ratas -admin -new
./ratas -server -admin
```

В своём мире команды доступны хозяину, на выделенном сервере — всем игрокам. Команды вводятся в чат (T), а F9 открывает окно с быстрыми действиями:

| Команда | Действие |
|---|---|
| `/god`, `/nocd`, `/heal` | бессмертие, умения без маны и перезарядки, полное здоровье |
| `/level N`, `/xp N`, `/gold N`, `/points N` | уровень, опыт, золото, очки навыков и характеристик |
| `/give предмет [кол-во] [редкость]` | предмет по ключу или части названия, например `/give long sword legendary` |
| `/items фильтр`, `/monsters фильтр` | списки ключей |
| `/spawn монстр [кол-во] [уровень]`, `/kill [радиус]` | призвать или убить монстров |
| `/tp X Y`, `/tp d3-2`, `/levels`, `/find имя` | телепорт в точку, на уровень, к NPC или монстру |
| `/unique ключ`, `/uniques` | поставить уникального персонажа рядом, список всех |
| `/unlock all` | открыть все секретные классы, подклассы и навыки |
| `/reveal`, `/time day`, `/speed N` | открыть карту, сменить время суток, ускорить бег |

`/help` выводит полный список.

## Графический режим

```bash
./ratas -gfx
```

Это та же игра, тот же сервер и протокол, но вместо терминала — окно. Игроки в терминале и в окне могут быть в одном мире одновременно.

* **Мир.** Тайлы — пиксель-арт 16×16. Его генерирует код из цветов в файлах контента, поэтому графику получают и тайлы из модов. Деревья, ели, горы, колонны и стены нарисованы в ракурсе 3/4 и сортируются по глубине: крона и стена закрывают того, кто стоит за ними. Вода и лава анимированы.
* **Существа.** Фишки-«миниатюры» с буквой из ASCII-версии, цветным ободком и тенью. Герой подпрыгивает на каждом шаге, у героя есть маркер направления взгляда, у боссов светящаяся аура. Над ранеными врагами — полоски здоровья, над другими игроками и ближними NPC — имена.
* **Свет.** Смена дня и ночи с тёплыми закатами и синими ночами. Видимость считается по тайлам и плавно размывается. В подземельях и ночью вокруг героя горит факел. Свет дают лава, снаряды, лестницы и алтари. Днём по земле плывут тени облаков, ночью летают светлячки, в подземельях — пылинки.
* **Эффекты.** У снарядов светящиеся шлейфы. Удары выбивают искры, смерть — брызги, новый уровень — золотой взрыв. Числа урона всплывают и гаснут, реплики персонажей показываются в пузырях.
* **Интерфейс.** Это тот же текстовый интерфейс, отрисованный настоящим шрифтом на полупрозрачных панелях со скруглёнными рамками и гладкими полосками. Мир виден сквозь боковую панель и журнал. В главном меню на фоне медленно проплывает сгенерированный ландшафт.

Дополнительные клавиши в окне:

| Клавиша | Действие |
|---|---|
| колесо мыши, Ctrl/Cmd + `=`/`-` | масштаб |
| F11 или Alt+Enter | полный экран |
| F12 | скриншот в `~/.ratas/screenshots` |
| мышь | клетка под курсором подсвечивается; ЛКМ — атака туда, ПКМ — умение 1, клавиши 1–6 тоже бьют в сторону курсора |

Клавиши движения в окне повторяются сами, пока их держат, поэтому бег получается ровным, без задержки автоповтора ОС. Закрытие окна сохраняет мир так же, как выход через меню.

**Сборка.** На macOS и Windows дополнительных зависимостей нет. На Linux Ebitengine нужен cgo и dev-пакеты X11/OpenGL (список — в [инструкции Ebitengine](https://ebitengine.org/en/documents/install.html)). Для выделенного сервера графика не нужна (`mise run build-server` или):

```bash
go build -tags nogfx -o ratas ./cmd/ratas
```

## Сетевая игра

1. Хозяин выбирает **Новая игра → Режим: Открыть для сети** или открывает уже идущую игру через **Esc → Открыть мир для сети**. В журнале появятся его локальные IP-адреса.
2. Друг выбирает **Присоединиться к миру** и вводит `IP:7777`. Если он заходит впервые, игра предложит выбрать класс.
3. Опыт за убитых монстров получают все игроки в радиусе 25 клеток, задания у каждого свои. Мир сохраняется у хозяина вместе с героями гостей, и при повторном входе под тем же именем гость продолжает с того же места.

Чтобы играть через интернет, откройте TCP-порт (по умолчанию 7777) на роутере или используйте VPN вроде Tailscale или ZeroTier.

Сервер авторитетный. Клиент отправляет только намерения, а сервер раз в тик присылает снимок ближайших сущностей, изменения тайлов, лог и диалоги. Одиночная игра устроена так же: это локальный сервер и клиент, соединённые через `net.Pipe`, поэтому протокол у обоих режимов общий.

## ИИ-персонажи (Claude)

Без ключа работает встроенный простой ИИ. С ключом Anthropic к нему добавляются:

* **Диалоги с NPC.** Пишите жителям что угодно. Каждый отвечает в характере своей роли (староста, торговец, кузнец, знахарка, стражник, житель), знает о ближайших подземельях, деревнях, времени суток и ваших заданиях, и помнит прошлые разговоры с вами. Если ИИ недоступен, работают готовые варианты ответов.
* **Действия NPC.** В ответе модель выбирает одно действие: дать золото или предмет, вылечить, выдать задание, открыть лавку, напасть на героя или закончить разговор. Ответ ограничен JSON-схемой (structured outputs), а игра дополнительно проверяет каждое действие: золото не больше, чем в кошельке NPC; подарки только из разрешённого списка и не чаще раза в 5 минут; цели заданий — только существующие монстры; лечение не чаще раза в минуту.
* **Тактика элитных врагов.** Атаман разбойников, болотная ведьма, гоблин-шаман, некромант и боссы примерно раз в 7 секунд боя просят Claude выбрать тактику: натиск, оборона, обход с фланга, отступление, позвать союзников или применить способность. Заодно они выкрикивают боевой клич. Встроенный ИИ продолжает действовать, пока ответ в пути: игра никогда не ждёт сеть.

Ключ можно задать двумя способами:
* **Настройки → API ключ Anthropic.** Ключ сохраняется в `~/.ratas/config.json` с правами 600.
* Переменная окружения `ANTHROPIC_API_KEY`.

Модель по умолчанию — `claude-opus-5-5`. Запросы идут с `effort: low`, чтобы ответы были быстрыми, и с серверным переключением на запасную модель при отказе (refusal fallback). В настройках можно указать `claude-sonnet-5-5` или `claude-haiku-4-5`: они отвечают быстрее и стоят дешевле. Встроенный лимит — не больше 40 запросов в минуту на весь мир. Если ключ отклонён, ИИ отключается до перезапуска и не засыпает API ошибками. В сетевой игре запросы отправляет только хозяин мира, гостям ключ не нужен.

## Генерация мира

* **Поверхность** (300×150). Высота задаётся фрактальным шумом Перлина минус радиальное затухание, поэтому получается остров. Влажность — независимое поле шума. Пороги вычисляются по квантилям, так что доля воды, гор и леса не зависит от зерна. Биомы: море, мелководье, пляжи, равнины с цветами и высокой травой, смешанный и хвойный лес, болота, холмы, горы и снежные пики. Реки стекают по склону от высокогорья к морю. 4–5 деревень с домами, колодцем и жителями ставятся на крупнейший связный участок суши и соединяются дорогами: взвешенный A* обходит горы и строит мосты через воду. Входы в 6 подземелий расставлены так, что чем дальше вход от старта, тем глубже подземелье.
* **Города.** В каждом мире 1–2 больших каменных города: крепостная стена с зубцами и четверо ворот, мощёные улицы, площадь с фонтаном, статуями и рынком, ряды каменных домов, фонари, которые светят ночью. В городе есть храм, ратуша, таверна, оружейная, кузня, лавка чародейки, алхимик, ювелир и казармы, а в них — горожане: бургомистр и капитан стражи дают поручения, трактирщик сдаёт комнаты, бард поёт песни-усиления, кузнец за плату поднимает редкость оружия, жрец благословляет. Городские торговцы кроме обычных товаров каждый день выкладывают редкие вещи — от необычных до легендарных. Ночью горожане собираются у таверны.
* **Склепы.** Комнаты получаются двоичным разбиением пространства (BSP) и соединяются коридорами. В проходах стоят двери, в комнатах — колонны, кости и обломки. Сундук ставится только там, где не перекроет путь.
* **Пещеры.** Клеточный автомат (правило 4–5) дорабатывается заливкой: остаётся только крупнейшая связная область. Шум добавляет лужи, а на глубине — лаву. Сундуки прячутся в тупиках.
* На последнем этаже каждого подземелья живёт босс. Этажи генерируются при первом посещении, монстры подбираются по теме и глубине. На поверхности монстры появляются вокруг игроков по биому и времени суток: ночью выходит нежить.

## Классы, редкость и деяния

* **Классы.** Стартовые: Воин, Плут, Маг, Жрец, Следопыт, Паладин, Монах, Скальд и Зельевар, у каждого ветка класса и три подкласса. Секретные классы — Шаман, Чернокнижник, Друид и Некромант. У каждого класса есть 2–3 секретных подкласса; их, как и секретные классы, открывают задания уникальных персонажей (до 40 в мире, слухи о них рассказывают жители).
* **Скрытые навыки.** У каждого класса 10 скрытых навыков. Они открываются сами за деяния: убить 300 врагов, увернуться от 200 ударов, сразить трёх боссов, пройти 30 000 шагов и так далее. В окне навыков (K) они видны как «???» с условием и прогрессом. Десятый навык класса открывается на 25-м уровне класса и даёт особое умение.
* **Редкость предметов.** Обычные, необычные, редкие, эпические и легендарные. Чем реже вещь, тем больше у неё случайных бонусов, тем они сильнее и тем выше её собственный урон или защита. Названия окрашены по редкости, а в окне редкие вещи на земле светятся. Именные артефакты легендарны; часть из них падает с боссов, часть изредка находится в глубоких подземельях.
* **Рыцарь** получает навык «Длинная рука»: с оружием ближнего боя он бьёт врага через клетку и по диагонали.

## Моды и расширение

Все определения лежат в `internal/content/data/*.toml`. Любые `*.toml` из `~/.ratas/mods/` (или из каталога, указанного флагом `-mods`) накладываются поверх встроенных:
* запись с существующим `key` заменяет встроенную;
* запись с новым ключом добавляется к остальным;
* при загрузке все ссылки проверяются: ветки, требования навыков, умения, предметы, типы урона и ключи характеристик;
* неизвестное поле — тоже ошибка с указанием места, так что опечатка не пройдёт незамеченной.

Моды в старом формате `*.json` по-прежнему загружаются.

Пример — [`mods_example/necromancy.toml`](mods_example/necromancy.toml). Он добавляет ветку «Некромантия» с четырьмя навыками, класс «Некромант», три умения, предмет и монстра. Чтобы подключить его:

```bash
mkdir -p ~/.ratas/mods
```

```bash
cp mods_example/necromancy.toml ~/.ratas/mods/
```

Каждая запись — таблица из массива: `[[skills]]`, `[[abilities]]`, `[[monsters]]` и так далее. Словари вроде `stats` удобно писать в одну строку, а вложенные эффекты (`on_hit`, `buff`) — подтаблицей сразу после записи.

### Навык

```toml
[[skills]]
key = "bone_spear"
name = "Костяное копьё"
branch = "necromancy"
tier = 2
max_rank = 3
level = 3
requires = ["grave_lore"]
grants = "bone_spear"
desc = "Открывает костяное копьё."
stats = { spell_pct = 4 }
```

* `stats` — бонусы за каждый ранг.
* `grants` — умение, которое открывается на первом ранге.
* `requires` — навыки, у которых должен быть хотя бы ранг 1.
* `level` — минимальный уровень героя.

Ветка задаётся отдельно: `[[branches]]` с полями `key`, `name`, `color`, `desc`.

**Ключи характеристик:**
* `str`, `dex`, `int`, `vit`;
* `max_hp`, `max_mp`, `hp_regen`, `mp_regen`;
* `armor`, `dodge`, `crit`, `crit_mult`;
* `melee_pct`, `ranged_pct`, `spell_pct`;
* `attack_speed`, `move_speed`, `sight`, `gold_find`;
* `life_leech` (вампиризм, % урона), `thorns` (урон атакующему в ближнем бою);
* для каждого типа урона: `res_<тип>` — сопротивление, `<тип>_pct` — бонус к урону, `add_<тип>` — добавка к удару оружием. Есть и групповые сопротивления: `res_physical`, `res_elemental`, `res_magic`, `res_all`.

Типы урона описаны в `damage.toml`: `slash`, `pierce`, `blunt`, `fire`, `cold`, `lightning`, `poison`, `arcane`, `holy`, `shadow`.

### Умение

```toml
[[abilities]]
key = "fireball"
name = "Огненный шар"
kind = "projectile"
mana = 10
cooldown_ms = 2500
dmg_type = "fire"
damage = [7, 12]
scale = "int"
scale_k = 1.3
range = 9
radius = 1
speed_ms = 60
glyph = "o"
color = "#ff8a2a"
desc = "Взрывается при попадании и поджигает."
[abilities.on_hit]
key = "burn"
name = "Горение"
duration_ms = 3000
dot_per_sec = 3
dmg_type = "fire"
color = "#ff6a1a"
```

Виды (`kind`):

| `kind` | Что делает |
|---|---|
| `projectile` | летящий снаряд; `count` — веер из нескольких, `radius` — взрыв |
| `nova` | удар по площади вокруг заклинателя; с `damage = [0, 0]` — проклятие без урона |
| `cleave` | удар по всем врагам рядом |
| `strike` | мощный удар по одному врагу |
| `chain` | молния, перескакивающая на `count` врагов |
| `heal` | лечит себя и союзников в `radius` |
| `dash` | рывок вперёд |
| `buff` | временный эффект на себя, а с `radius` — и на союзников |

`dmg_type` — тип урона (`weapon` — тип текущего оружия), `leech` — доля урона, которая лечит заклинателя.

`on_hit` вешает эффект на цель: урон во времени (`dot_per_sec` и его `dmg_type`), оглушение (`stun = true`) и/или временные `stats`, например `stats = { res_fire = -30 }` снижает сопротивление огню.

Новый вид умения пишется на Go один раз, после чего его можно использовать в любом количестве умений из файлов данных:

```go
game.RegisterAbilityKind("teleport", func(g *game.Game, c *game.Entity, a *content.AbilityDef, t *game.Entity) bool {
    // ... ваша логика; вернуть false, если применить нельзя
    return true
})
```

### Остальное

* **Классы** (`classes`): стартовые `attrs`, `abilities`, `items`.
* **Монстры** (`monsters`):
  * `behavior` — `melee` или `ranged`; `ability` — умение монстра;
  * `depth` — диапазон этажей; `[0, 0]` — только поверхность, `[0, n]` — поверхность и этажи до n;
  * `themes` — темы подземелий (`cave`, `crypt`, `ice`, `volcano`, `temple`, `fortress`) или биомы поверхности;
  * `dmg_type` — тип урона в ближнем бою, `resist` — сопротивления, например `resist = { poison = 100, holy = -50 }`;
  * `on_hit` и `on_hit_pct` — эффект и его шанс при ударе; `model` — модель в графическом режиме;
  * `group` — размер стаи;
  * `night` — монстр появляется только ночью;
  * `elite` — тактику выбирает Claude; `boss` — босс последнего этажа; `drops` — гарантированная добыча;
  * `persona` — характер для ИИ.
* **Предметы** (`items`):
  * `kind` — `weapon`, `armor`, `trinket` или `consumable`;
  * `stats`, `damage`, `heal`, `mana`, `value`;
  * оружие: `dmg_type`, `on_hit` с шансом `on_hit_pct`;
  * расходуемое: `buff` (эффект на героя) и `effect` — `cleanse`, `return`, `respec` или `xp` (с силой `amount`);
  * `depth`, `weight` — шанс выпадения.
* **NPC-роли** (`npcs`): приветствия и реплики, `trader` с товарами `goods`, `quest_giver`, `persona` для ИИ, `count` — сколько таких NPC в деревне.
* **Тайлы** (`tiles`): `glyph`, цвета, `walkable`, `transparent`, `move_cost`, `damage` (урон в секунду, как у лавы) и его `dmg_type`, `light` — цвет свечения в графическом режиме, а для интерактивных тайлов — `interact` (`door`, `chest`, `shrine`, лестницы) и `becomes`. Новые тайлы добавляйте в конец списка: номер тайла в сохранениях — его позиция.

## Сохранения

* Сохранения лежат в `~/.ratas/saves/*.sav`. Путь можно поменять переменной `RATAS_HOME`.
* В сохранение попадают все уровни (включая изменённые тайлы: открытые двери и сундуки), монстры, NPC с их памятью и кошельками, а также все когда-либо входившие герои с их картой исследования.
* Загрузить сохранение можно через **Загрузить** в главном меню и продолжить его в одиночку или открыть для сети.

## Архитектура

```
cmd/ratas           точка входа, флаги, выделенный сервер
internal/content    контент в TOML, моды, валидация
internal/gen        шум Перлина, поверхность, склепы (BSP), пещеры (клеточный автомат)
internal/world      карта уровня, поле зрения, линия видимости, A*
internal/game       симуляция: сущности, бой, умения, ИИ, диалоги, спавн, сохранения
internal/llm        Claude: диалоги NPC и тактика (Anthropic Go SDK, structured outputs)
internal/proto      протокол клиент-сервер (gob), сжатие уровней
internal/server     игровой цикл 20 тиков/с, сессии, TCP, автосохранение
internal/client     tcell-интерфейс: меню, рендер карты, HUD, окна
internal/gfx        графическое окно: тайлы, фишки, свет, частицы, отрисовка интерфейса шрифтом
tools/contentgen    генератор части контента вместе с английским переводом (Python)
```

Симуляция однопоточная и принадлежит серверной горутине, поэтому блокировки ей не нужны. Асинхронные ответы Claude возвращаются через `Game.Post`.

## Релизы

Релизы собирает GitHub Actions (`.github/workflows/release.yml`). Чтобы выпустить версию, достаточно отправить тег:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Workflow прогоняет тесты на Linux, Windows и macOS, собирает архивы на своих машинах, проверяет, что каждая сборка запускается и сообщает правильную версию (`ratas -version`), считает `SHA256SUMS.txt` и публикует релиз. В заметки к релизу попадают инструкция по установке (`.github/release-notes.md`) и список изменений с прошлого тега. Теги с дефисом, например `v0.2.0-beta.1`, публикуются как пре-релизы.

Релиз можно выпустить и без тега из консоли: Actions → Release → Run workflow, ввести имя тега — он будет создан на выбранной ветке.

Один архив можно собрать и локально, тем же скриптом:

```bash
scripts/package.sh windows-amd64 v0.2.0    # windows-amd64, windows-arm64, linux-server-amd64 — с любой ОС
scripts/package.sh macos-universal v0.2.0  # только на macOS
scripts/package.sh linux-amd64 v0.2.0      # только на Linux, нужны cgo и dev-пакеты X11/OpenGL
```

При каждом пуше и пулл-реквесте `.github/workflows/ci.yml` проверяет форматирование, `go vet` и тесты на всех трёх ОС.

## Тесты

```bash
go test ./...
```

Что покрыто:
* генерация: связность, достижимость лестниц, входов и боссов;
* игровая симуляция: передвижение, бой, опыт, навыки, сохранение и загрузка, долгий прогон со случайными действиями нескольких игроков;
* сетевая игра по TCP;
* интеграция с Claude на поддельном API-сервере: формат запроса, разбор ответа, выдача задания NPC;
* загрузка модов;
* интерфейс в симулированном терминале, в том числе передача мира графическому рендереру.

Графический режим проверяется сценарием со скриншотами: он открывает окно, проходит меню, день, ночь, бой в подземелье, диалог и окна и сохраняет кадры в указанную папку:

```bash
RATAS_GFX_SHOTS=/tmp/ratas-shots go test ./internal/gfx
```
